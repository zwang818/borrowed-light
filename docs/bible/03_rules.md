# 03 · Rules（规则与状态边界）

## 1. 进度与胜负

固定顺序推进五个主要场景；结尾复用荒原。必要武器与关键主线事件在必经路，日志收集不决定通关或结局分支。耐久归零进入死亡流程，不存在照明或弹药耗尽失败。击败 Boss 不是完整通关，必须完成同步和结尾。

武器、普通敌人和 Boss 的行为边界见 [02_entities.md](02_entities.md)，操作见 [05_ui_hud.md](05_ui_hud.md)。

## 2. 伤害与物理质量

### COMBAT-03 · 伤害与物理质量

只有玩家在有效受伤后进入短暂无敌，避免同帧或一次接触连续扣完耐久。普通敌人和 Boss 默认没有受击无敌，每颗有效弹丸分别结算伤害，包括同帧命中的不同散射弹丸；同一颗弹丸仍只能结算一次。视觉受击闪烁不等于无敌，不得用闪烁动画或共用受伤计时器屏蔽敌人后续命中。受伤与命中均有可辨认反馈。机关预警阶段不伤害，生效阶段按规则结算。普通实体接触不偷带持续扣血，清扫者攻击使用明确的攻击时段和范围。

墙和关闭的实体门挡住身体及普通弹丸；脉冲激光遇这些实体表面或地图边界停止，不反射也不穿墙。激光每束对同一敌人只伤害一次，遇敌停止延伸；敌人离开后可照射其后方，原敌人重返同束不再次受伤。不能隔墙交互或把攻击起点生成在墙另一边。高速移动必须防止漏检薄墙和目标，具体用扫掠或等效方案均可。移动、冷却、蓄力、激光时长及预警与帧率无关。

## 3. 照明、探索与协议

### VISION-01 · 三态必须都有

| 区域状态 | 允许显示 | 禁止行为 |
| --- | --- | --- |
| 未探索 | 黑暗或雾，少量自发光地标 | 预先画完整隐藏空间 |
| 当前可见 | 范围内无遮挡的地形、物件、敌人与提示 | 透墙显示敌人 |
| 已探索但当前不可见 | 低亮度静态轮廓、已发现门和终端标记 | 继续显示敌人实时位置 |

近身圆形灯固定基础范围、默认开启、不耗电，不随鼠标控制方向。维修终端可恢复区域固定灯并提供可见反馈。

### VISION-02 · 不允许用特效冒充系统

光照表现、墙体遮挡可见性、探索持久记录、敌人识别分别定义和验证。灯光节点不自动生成空间记忆。按小房间或预划分区域记录，但不能用大触发器顺带揭开隔墙房间。死亡不抹除本局探索。

### VISION-03 · 公平性

不可辨认位置不得无预警立即伤害玩家；敌人先进入可辨认范围或给明显提示。发光弹丸、机关预警和 Boss 危险格必须可读，不得被雾掩盖。不能为了氛围让玩家反复死亡猜路线。

### VISION-04 · 统一可见性与敌人发现行为

本表为本次修订采用的基础行为，所有模块共同使用，不由灯光、美术和敌人脚本各自解释。

- **有效照亮**：位置处于主角光域或已启用固定灯的有效覆盖内，光源到该位置的路径未被实体墙或关闭的实体门阻断。
- **当前可见**：对象位于玩家当前房间，位置有效照亮，且玩家到对象的视线无遮挡。固定灯可扩大本房间内玩家能看清的区域，但不扩大主角灯本身半径，不提供墙后、转角后或其他房间的远程视野。
- **玩家可辨认敌人**：敌人当前可见，且出现在游戏画面的可读范围内。用于基础版普通敌人的公平性门槛；地图记忆和屏幕外亮光不能替代它。
- **有效发现玩家**：敌人满足自身检测距离与无遮挡视线，同时玩家可辨认该敌人；清扫者还要求玩家未处于协议状态。灯亮不等于敌人自动取得攻击资格。

| 情况 | 可见性与记忆结果 | 敌人行为 |
| --- | --- | --- |
| 启动固定照明 | 扩大当前房间内实际无遮挡的可见范围；新可见静态区域进入记忆 | 仍需检测距离、视线和画面可辨认条件，不因通电直接开火 |
| 固定灯照到墙后或其他房间 | 玩家未取得视线的区域不显示动态敌人、不新增探索记录 | 不通过灯光共享墙后目标 |
| 哨机尚未被玩家看见或位于画面外 | 不把已探索标记当成当前可见 | 不锁定、不启动预警、不发射 |
| 哨机预警或连射途中失去有效发现条件 | 地形记忆保留，动态状态按当前可见性显示 | 取消剩余未发射弹丸并解除锁定；重新发现后重新完整预警 |
| 清扫者失去有效发现条件 | 不使用实时墙后玩家坐标 | 当次更新立即取消追击、预警与攻击伤害区，停止冲撞，进入恢复，再回原巡逻路线；不继续追踪最后位置 |
| 清扫者重新发现玩家 | 正常可见与记录 | 从接近和完整预警重新开始，不能接续上次未完攻击直接命中 |
| 协议激活时清扫者已锁定、预警或攻击 | 协议外观立即生效，探索记录不变 | 在伤害结算前撤销锁定、关闭攻击伤害区、停止冲撞并进入恢复；恢复后巡逻，不再选择协议玩家 |
| 协议结束后仍处于发现范围 | 按普通状态重新判断 | 重新接近和完整预警，不因退出协议立即扣血 |

取消攻击只取消尚未发生的伤害，不返还已合法扣除的耐久。协议状态必须先更新，再处理本次敌人攻击资格和伤害；已经发射的哨机弹丸继续按原轨迹、碰撞和寿命运行，不能因为炮台不再可见就悄悄消失，弹丸进入画面仍须可读。协议不取消哨机、Boss 或机关伤害。

Boss 战使用全场应急照明和专用攻击规则；不因普通敌人的协议过滤停机。以上“立即取消”指条件变化被处理的同一次游戏逻辑更新，不增加一段未配置的攻击宽限。

### PROTOCOL-01 · 协议不是无敌或穿墙

只在指定终端激活、指定检修区生效，变暗并显示蓝色轮廓。可绕过清扫者识别、打开授权门；不可穿墙、免疫机关、骗过哨机或 Boss。协议有效时不能造成玩家攻击；开启攻击接口必须先退出协议。离开区域即结束。首次攻击输入是否只退出而不射击属于待定输入细节，不能伪装成原方案已经决定。

## 4. 状态、交互与重试

### STATE-01 · 房间基线、提交与重试

本次修订采用“进入房间保存基线，死亡恢复基线，成功进入下一房间后提交”的规则，替代原 OPEN-03。此为文档规则，尚未通过样板房间验证；不代表已经实现跨程序存档。

1. 首次进入房间：初始化房间及安全出生状态，然后保存重试基线。基线包含房间敌人、机关、终端、门、固定灯及相关世界进度标记，不包含弹丸和攻击残留。
2. 房间内操作属于未提交变化。启动终端、打开门、恢复固定灯、击败敌人或播放剧情，不单独刷新基线。
3. 玩家仍存活且下一房间已经加载成功、合法落点已经建立，才一次性提交离开房间的变化，并建立下一房间基线。仅碰到出口、播放转场或加载失败不算成功，不得部分提交。提交前死亡仍回原房间。
4. 返回已访问房间时，从该房间上次已提交状态初始化，再建立本次入口基线；不任意抹除此前已提交进度。任何成功的合法跨房间移动都采用同一提交规则，包括近路和返回旧房间。
5. 最终同步是终局特例：Boss 击败本身不提交；安全完成同步后提交通关状态并转场荒原，不要求再穿过普通房门。

| 内容 | 当前房间死亡后 | 成功进入下一房间后 |
| --- | --- | --- |
| 玩家位置 | 回当前房间入口；Boss 回门前恢复点 | 使用新房间合法入口 |
| 耐久 | 按检查点配置恢复，数值仍见 OPEN-05 | 不因提交自动回血，维修与检查点效果单独处理 |
| 当前房间敌人 | 恢复基线状态；本次未提交击杀撤销 | 保存离开时的房间状态 |
| 机关 | 回基线规定的安全初始周期，无残留伤害 | 保存需要保留的配置和开关状态，不持久化运行中的攻击计时 |
| 终端、门、固定灯 | 包括已经操作过的对象，一律恢复入口基线 | 提交离开时状态，包含其关联门和灯的效果 |
| 相关世界进度标记 | 随终端、门等一起回滚到基线，避免标记与场景分离 | 与对象状态一并提交 |
| 武器、探索区域、已读日志、已看剧情 | 本局即时保留，不随世界回滚 | 继续保留，不重复发奖 |
| 已看剧情关联的世界效果 | 叙事不重播；可回滚效果由可重复触发的交互或独立事件重新执行 | 随世界进度提交，不能靠“已看过”布尔值猜门状态 |
| 门、终端地图标记 | 重建为回滚后的真实状态，已探索地形轮廓仍保留 | 显示已提交真实状态 |
| 其他房间已提交进度 | 保持不变 | 只提交本次离开房间及其明确关联的世界效果 |
| 协议、弹丸、攻击锁定、伤害区及过期计时器 | 不保留旧运行状态；清除后按安全入口与区域条件重新初始化 | 不带入下一房间 |

**明确示例**：进入房间时终端未启动、门关闭、固定灯熄灭；操作终端开门亮灯，但尚未成功进入下一房间便死亡，则终端恢复未启动、门关闭、灯熄灭。此次照亮的空间、取得武器、读过内容保留；再次操作终端仍可开门，不重播已看对白。若已成功跨房间提交，再回到此处，门和灯保持已提交状态。

恢复顺序：停止当前战斗与计时 → 清理运行对象 → 还原基线世界与关联标记 → 叠加独立保留的武器和记忆数据 → 更新地图及可见性 → 放置玩家并恢复输入。不能重复生成敌人、重复发奖或因跳过对白导致软锁。完整存档未实现时不提供虚假的“继续游戏”。

### STATE-02 · 数据分离

探索记忆与实际世界状态分离；已播剧情与进度效果分离；本局跨场景数据与当前房间运行状态分离。用稳定 ID 标记房间、区域、日志、终端、门、事件、检查点和武器，不用临时节点路径代替存续身份。

### STATE-03 · 交互与暂停

E 只作用于当前一个有效目标，必须满足距离、遮挡和业务条件。同一次输入不应既打开又跳过对话，也不能关窗同时射击。长对话和暂停冻结战斗、机关、弹丸与伤害计时，恢复后不补算暂停时间。记忆界面的暂停策略按待定项处理。

## 5. 验收门槛

不能用绕过、删测试、吞错误、永远返回成功或临时无敌来冒充修复。按改动影响选相关检查；纯文档不必跑全游戏，玩法未实现的检查标“尚不适用”，不能标“通过”。

| 检查编号 | 场景 | 通过条件 |
| --- | --- | --- |
| QA-01 | 启动、资源和引用 | 已实现主入口正常，无新增阻断错误 |
| QA-02 | 移动、隔墙交互和射击 | 斜走不加速，实体不穿墙，隔墙不能误触或生成弹丸 |
| QA-03 | 相邻隔墙空间、探索后离开 | 无透墙揭图；离开保留轮廓、不显示实时敌人 |
| QA-04 | 探索、拿武器、读日志后死亡 | 保留表正确，门和终端标记与世界一致，无重复奖励 |
| QA-05 | 多枚弹丸同帧命中玩家、普通敌人与 Boss | 玩家按受伤无敌只结算合法扣血；敌人和 Boss 每颗有效弹丸独立结算，闪烁不吞伤害 |
| QA-06 | 协议进清扫者、机关和哨机范围 | 清扫者不锁定，其他危险仍有效，无协议内攻击 |
| QA-07 | 对话、暂停和关闭窗口 | 世界按规则冻结恢复，无补算或输入穿透 |
| QA-08 | Boss 死亡与玩家失败重试 | 直接重试；胜利后无残留伤害，可安全同步 |
| QA-09 | 主线通关、不读日志 | 营救成立、教学可懂、结尾完整，记录真实时长 |
| QA-10 | 读全部日志通关 | 同一结局事件，线索可解释，无直接揭底 |
| QA-11 | 中文、静音、密集音效 | 使用实际 HUD、日志与对话文案无缺字；静音可读危险，关键音不被淹没 |
| QA-12 | 开门亮灯后，跨房间前死亡 | 门、终端和灯回入口基线，记忆保留，再操作可通行 |
| QA-13 | 成功跨房间、返回旧房间、在新房间死亡 | 已提交旧房间进度保留；当前房间回自己的基线；失败转场不得提交 |
| QA-14 | 固定灯、墙体、画面边缘与哨机 | 灯仅扩大无遮挡可见区域；未被看见的哨机不锁定开火，丢失条件取消未发射攻击 |
| QA-15 | 清扫者丢失视线、攻击中激活协议 | 同次更新取消追击与伤害；再次发现或退出协议后重新预警，不瞬间命中 |

修改主线或跨场景状态时，在已有流程可运行的前提下完整回归。无法启动引擎或缺少测试环境必须明确说明原因及待验证步骤，不能凭阅读代码宣称验收完成。
