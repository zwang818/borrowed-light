## 3. 两份 Bible 的冲突裁定

| 编号 | 差异或问题 | 统一处理 | 理由 |
| --- | --- | --- | --- |
| M001 | 两份文档都可能被当作当前依据，doc1 自称优先 | 唯一在用规则为 docs/bible；旧稿和独立条例归档 | 消除相互覆盖，保留可追溯材料 |
| M002 | 原方案建议四组线索，doc1 禁止第五条 | 保留四组核心含义，允许四至六条日志与环境呈现 | 线索组不等于具体物件数量，不擅增新的真相 |
| M003 | 三格耐久和调参建议被写成最终铁律 | 三格作临时默认，数值表是参考起点 | 没有试玩或小组确认记录 |
| M004 | doc1 暂定 32px，却另列瓦片尺寸待定 | 最终尺寸待定；32px 仅可用于临时灰盒 | 避免资产制作被未确认数字绑定 |
| M005 | 每类敌人 1–3，与每房间普通敌人 1–3 冲突 | 普通战斗房总数 1–3 是原型起点；安全区可零敌人 | 不把少量敌人误写成每房间强制战斗 |
| M006 | “敌人不做追击寻路”与清扫者接近玩家冲突 | 清扫者保留接近与必要简单绕障；哨机和 Boss 固定 | 维护原方案敌人分工 |
| M007 | doc1 强制 AudioManager，工程没有该系统 | 声音反馈和清理强制，管理器架构不强制 | 不能虚构依赖或为了规范过度设计 |
| M008 | doc1 禁止出现函数变量名，但命名章节大量使用 | 允许工程规范使用具体命名示例 | 避免文档自相矛盾 |
| M009 | 协议第一次按键只退出既被写死又列待定 | 只锁定协议内不能攻击；首次按键语义继续待定 | 原方案没有指定吞掉首次输入 |
| M010 | 已完成终端如何重试，两份都不完整 | 初版列 OPEN-03；本轮已转 STATE-01，明确入口基线与成功跨房间提交 | 保留历史来源，以现行恢复表消除跨房间软锁歧义 |
| M011 | 两份仍写引擎版本待定，README 已有约定 | 保留仓库现有版本记录、渲染与主场景 | 不擅自重建或升级；未核验本机版本不冒称已核验 |
| M012 | 旧目录图要求 scenes/main/，实际为 scenes/main.tscn | 保留实际主场景，目录按需建立 | 示例结构不能覆盖现有引用 |
| M013 | doc1 任何合并前要求全部验收 | 按影响检查；阶段未实现项目标不适用，完整交付必须全覆盖 | 文档改动不应假装完成尚不存在的玩法测试 |
| M014 | “两行文字多一个字都不行” | 保留既有文案语义，不禁止正常换行标点 | 防止解释性泄底，同时允许正常排版 |
| M015 | 所有变更必须群里讨论 | 明确用户授权可直接落实，重大未定项询问；不擅自发群消息 | 用户指示优先，避免多余审批与未经授权外发 |
| M016 | 稳定 ID 被引用后永不许改名 | 禁止无迁移改名；允许授权变更同时修复引用与迁移 | 稳定性约束不应阻止必要修复 |
| M017 | HUD 位置、禁止配音等表现建议被绝对化 | 保持必要信息、无虚构资源；布局可调，完整配音不纳入基础范围 | 锁范围和效果，不锁无依据的实现细节 |

## 7. TITLE-001 · 标题界面原型（2026-10-20）

- **授权依据**：用户要求制作可方便后续美术调整的标题界面，并明确要求金色立体字、左下角英文水印、维特根斯坦哲学引句及右侧动态机器人存档入口。
- **旧行为**：主场景居中显示游戏名称，无独立标题模块和菜单交互。
- **新行为**：保留主场景入口，实例化分层标题场景；荒原、机械神兽、机器人、光晕、标题和按钮可分别调整。引句为“世界的意义，必定在世界之外。”（据《逻辑哲学论》6.41 英文首句自译）。机器人点击打开真实的空存档面板，支持鼠标、键盘聚焦和 Esc 关闭；开始按钮待接第一关，退出可用。
- **影响模块**：`scenes/main.tscn`、`scenes/ui/title_screen/`、新增标题 SVG 和许可字体、README、05 UI Bible、标题编辑说明与素材来源记录。未修改引擎配置、输入映射、Autoload、碰撞层或其他玩法。
- **范围边界**：几何占位美术及 1280×720 排版参考不解决 OPEN-01；完整存档读写、关卡和设置未实现。存档空面板不等于游戏内地图／日志记忆界面，也不增加基础必交付系统。
- **验证结果**：macOS / Godot 4.7.2 图形运行验证当前文案字形覆盖、主场景启动、16:9 与 4:3 适配、机器人待机动态、真实鼠标点击、弹窗焦点、Esc 和关闭按钮、缩放后的点击位置，以及临时内存目标场景跳转；前一版已验证真实退出按钮结束进程。人工 F5 / F6、Windows、导出版本和完整流程未在本条中宣称通过。
