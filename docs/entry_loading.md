# 进入第一关的加载界面

2026-11-09，按用户提供的 CSS 横条样例接入 Godot：120×20 浅灰底，黑色从左向右填充。按用户后续要求放慢为约三秒单次推进，等待时最多九成，不再循环归零。屏幕采用暗色底，居中显示 LOADING，不显示虚构百分比。

加载条上方复用标题的 `xiaoyi_greeting.png` 和原动作帧，由加载专用 `loading_robot_animation.gd` 组合约七秒循环：招手、左右晃动、蹲下轻跳、落地缓冲、小步挪动、点头式摆动，再招手。短加载的前三秒也能看到招手、晃动和轻跳。小一约 124 像素高，动作围绕脚底锚点，不推动进度条布局；游戏暂停和场景切换等待期间仍会动，不拦截鼠标。没有新增图片或许可依赖，标题本身仍沿用原九秒动作及存档点击入口。

开场点击“进入游戏”、跳过开场或开场自然结束均走同一入口。`intro_cutscene.gd` 不再在 `_ready` 同步加载第一关，改由 `entry_loading.gd` 使用 ResourceLoader 线程请求；Inspector 显式指定的 PackedScene 仍优先使用。重复进入请求被拦截。

加载页至少等待三秒，资源读取成功后切换场景；第一关完成实例化并经过首批帧后，才用 0.25 秒将最后一段填满，随后撤去遮罩并恢复操作，避免先显示加载完成、关卡却还未准备好。期间世界暂停、输入被消费。若资源较慢，横条停在九成继续等待；条形动画是等待指示，不代表真实加载百分比。读取或切换失败显示 LOAD FAILED，可按 RETURN 回原开场重试。

复用现有游戏主题与字体，只使用基本 ASCII 文案和 Godot 控件，无新增图片、字体或外部许可依赖。未修改工程配置、输入映射、Autoload 或主场景。

验证入口：`godot --headless --path . --script res://tests/manual/c_progress/progress_check.gd`，末段检查标题→开场→加载→第一关，以及加载期间暂停和重复进入保护。实际窗口另检查居中条形布局。仍待非作者实际点击与其他平台复测。
