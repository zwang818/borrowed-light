# 标题存档与继续游戏

2026-11-09 用户要求在开始界面加入实际存档系统。本轮提供一个本地旅程档案，与独立的成就记录分开。

## 玩家操作

- 没有有效存档时标题显示“开始游戏”，进入开场，再进入第一关建立记录。
- 有有效存档时显示“继续游戏”，通过加载页直接进入第一关，不重复开场。
- 点击标题机器人打开“记忆档案”，查看保存时间、图纸／能力阶段、已解锁管道数量，可读取、开始新旅程或删除。
- 新旅程覆盖和删除均需再次点击确认；关闭或 Esc 取消确认。开始新旅程的开场未结束前，不覆盖旧旅程文件。
- 图纸、制造、故事记录及管道解锁完成后自动保存；返回标题前保存；暂停菜单也可选择“保存游戏”，保存结果以短通知显示。

## 保存边界

第一关通关自动保存后显示加载页返回标题，不播放第二关进场。保存可选布尔字段 `first_level_cleared`：旧版本 1 记录缺少字段时按未通关读取；新记录保存完成结果。标题和档案显示“第一关已通关”，读取按钮改为“重玩第一关”，复用现有知识按入口重玩，已通关标记不会因重玩或房间重试清除。开启新旅程才建立新的未通关记录。正式 F5 旅程会自动保存；独立 F6／测试场景沿用隔离路径，不覆盖个人旅程。

采用房间入口续玩：保存图纸知识、已学脉冲能力、已读故事与口令线索、管道解锁及当前已有探索记录。读取时从第一关安全出生点按原房间重试耐久恢复，已学能力可直接使用，不重复制造；敌人、终端、两道门与蛛网恢复基线，需重新清场／验证口令。

不恢复战斗中的瞬时位置、残留弹丸、敌人攻击时段或临时菜单；不新增复活点，不裁定 OPEN-05 的后续正式数值。当前探索记录仍不是完整可见性系统。后续跨关提交、第二关及其他关卡尚未接入，存档只接受当前已运行的腹腔场景。

## 文件与恢复

默认 `user://journey_save.json`，版本 1；写入 `.tmp` 后校验，再以 `.bak` 保留上一份可读记录并替换主文件。主文件损坏可回退备份，并在档案提示“备份恢复”；两份都损坏时禁用读取，不显示虚假的可继续状态，可确认开始新旅程或删除损坏记录。写入失败提示错误，返回标题前保存失败则停留当前场景，避免无提示离开。

JSON 仅保存普通数据，校验版本、场景白名单、字段类型与数量／坐标范围，不执行文件中的资源或脚本。删除旅程会清主文件、备份及临时文件，但保留 `achievements.cfg`。没有新增 Autoload 或工程配置。

`journey_save.gd` 提供 `read_save`、`write_save`、`erase`。标题通过 SceneTree 的一次性 `journey_session` 元数据传递已校验记录及路径，第一关消费后移除；关卡只在该会话启用保存。直接 F6／独立检查场景不会自动建立或覆盖个人旅程。
